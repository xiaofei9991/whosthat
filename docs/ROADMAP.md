# Who's That? 产品蓝图（Product Blueprint）

> 无剧透的影视角色速查工具。solo founder，预算 $100，目标：从英语市场赚到第一笔美元收入。
> 本文档是执行手册，不是 PPT。每个阶段都有明确的 kill/continue 判断标准。

---

## 1. 产品愿景与定位

**一句话**：看剧时随时回答"这个人是谁？我在哪见过这个演员？"——且绝不剧透你还没看到的内容。

**为什么是现在（Why Now）**

- 群像剧时代：流媒体大剧动辄 20+ 主要角色（权游、繁花式群像已成主流），"记不住谁是谁"是大众痛点，不只是小众需求。
- 需求已被反复验证但没人做工具化：Yahoo、Town & Country 等主流媒体为每部大片**手工**撰写 "spoiler-free character guide" 文章（如 The Odyssey）——他们在用编辑人力做本该由程序做的事。
- Amazon X-Ray 证明了 UX 价值，但被锁死在 Prime Video 内。Netflix/Disney+/HBO 用户没有等价物。
- 直接竞品为零（唯一相邻产品 story-who.fawwaz.dev 只做书籍）。
- 社区信号明确：r/SomebodyMakeThis 有脸盲用户逐字描述了这个产品；r/Prosopagnosia 长期重复抱怨追不住剧中角色。

**三类目标用户（Persona）**

| Persona | 场景 | 核心诉求 | 付费意愿 |
|---|---|---|---|
| 脸盲（prosopagnosia）观众 | 每次换场景就认不出人，严重影响观剧体验 | 可靠、随手可查的角色对照表；理想是实时叠加在播放器上 | **高**——这是刚需与无障碍需求，是种子社区与 Pro 订阅核心 |
| 群像剧普通观众 | 追《继承之战》类多线群像，隔周忘角色 | 快速回忆"这人是谁、和谁什么关系"，**不被剧透** | 中——广告流量主力，部分转化订阅 |
| "这演员我在哪见过"时刻 | 看片途中脸熟抓狂，去 Google 反被剧透 | 一键展开演员其他代表作 | 低——但搜索量巨大，是 SEO 流量入口 |

**定位边界**：不做影评、不做评分、不做社交。只做一件事——安全地告诉你"这是谁"。护城河 = spoiler shield（IMDb/Google 做不到无剧透）+ SEO 页面矩阵先发。

## 2. 完整产品形态：三阶段

### V1 — MVP + SEO 基建（已完成 / 进行中）

| 功能 | 状态 |
|---|---|
| 搜索任意电影/剧集 → 角色卡片墙（剧照、角色名、演员名、集数） | ✅ 已上线 |
| "Where do I know them from?" 展开演员其他代表作 | ✅ 已上线 |
| 剧集 spoiler shield：选择"我看到第 N 季"，只显示已出场角色 | ✅ 已上线 |
| TMDB 服务端代理（key 不暴露） | ✅ 已上线 |
| SEO 基建：每部片独立 URL、动态 meta、sitemap | 🔧 进行中 |

V1 唯一目标：**让 Google 能收录、让种子用户能用**。不加任何新功能，先把 SEO 基建做完。

### V2 — 增长版（第 3–8 周）

按投入产出比排序，逐个上线：

1. ✅ **"Who plays X in Y" pSEO 页面**——每个角色一个问题页（详见 §3）。这是流量杠杆最大的一项，优先做。
2. ✅ **集级 spoiler shield**——从"看到第 N 季"细化到"看到第 N 季第 E 集"。实现：整季用 season aggregate_credits，零头集数逐集拉 episode credits（含 guest stars）合并。
3. ✅ **分享卡片（OG image）**——`api/og.js`（edge + `@vercel/og`）动态生成 1200×630 卡片，`api/page.js` 已接入 og:image。
4. ✅ **Watchlist / 观看进度记忆**——`src/progress.js`（localStorage），剧集页 shield 选择自动保存并在回访时恢复，首页新增 "Your shows" 区块。
5. ✅ **PWA**——vite-plugin-pwa（autoUpdate + workbox 运行时缓存 TMDB API/图片），图标由 `scripts/generate-icons.mjs` 生成。
6. ✅ **sitemap 自动放量**——按天线性增长（1000 → 5000，每天 +60），顺序只追加不重排，兼顾新域名爬取预算与长尾覆盖；无需人工盯。
7. ✅ **多语言（中英）**——`src/i18n.js`（字符串字典 + localStorage `wt.lang`，浏览器语言自动检测），api.js 全局带 TMDB `language` 参数，静态页有中文版，头部有 中/EN 切换（切换即整页 reload 重取数据）。

### V3 — 变现版（第 9 周起，前提：V2 指标达标）

1. **浏览器插件（核心付费点）**——Chrome/Edge 扩展，叠加在 Netflix/Disney+ 网页播放器上：读取当前播放的剧集与时间点，侧边栏实时显示"当前出场角色"。即"人人可用的 X-Ray"。技术路径：读取播放器 DOM 拿到 title + 进度 → 调自家 API → 按集过滤角色。先只支持 Netflix 网页版，跑通再扩。
2. **AI 无剧透角色描述 + 关系图**——用 LLM 基于"只看到第 N 集"的约束生成角色简介与关系图（"X 的哥哥，第 2 集出场"）。按需生成 + 强缓存（同一片同一进度全网只生成一次），控制 API 成本在个位数美元/月。
3. **观影中实时模式（网页版）**——不装插件的降级方案：手动输入"我在看 S02E05 第 20 分钟"，显示该时点前已出场角色。
4. **Pro 订阅**——插件 + 实时模式 + AI 关系图 + 无广告打包（详见 §4）。

## 3. SEO / 流量策略

**核心逻辑**：影视角色查询是天然的长尾关键词金矿，且用户意图与产品 100% 匹配。用 TMDB 数据程序化生成页面矩阵，抢在无竞品状态下占位。

### pSEO 页面矩阵

| 页面类型 | URL 模式 | 目标关键词 | 规模量级 |
|---|---|---|---|
| 片/剧 cast 页 | `/title/{slug}` | "{title} cast", "{title} characters" | 数万（按热度分批生成） |
| 角色问题页 | `/who-plays/{character}-in-{title}` | "who plays {X} in {Y}" | 每片 10–30 个 × 片库 = 数十万潜力 |
| 每季 guide 页 | `/title/{slug}/season-{n}` | "{title} season {n} characters", "spoiler free guide" | 剧集 × 季数 |
| 演员页（V2 后期） | `/actor/{slug}` | "{actor} movies and tv shows" | 竞争激烈，优先级最低 |

**执行要点**

- **不要一次性生成全库**。Google 对新站海量薄页会降权。第一批只做 TMDB trending/popular 前 500 部，页面内容做厚（角色列表 + 集数 + 无剧透简介 + 内链），确认收录质量后再扩量。
- **内链结构**：cast 页 ↔ 角色问题页 ↔ 每季页互链，sitemap 按类型分文件提交。
- **新片自动蹭热点**：定时任务（Vercel cron，免费）拉 TMDB upcoming/on-the-air，新片上线当天自动生成页面并更新 sitemap。大剧首播周是 "who plays..." 搜索量峰值，媒体手工文章要 1–3 天，我们是零延迟。
- **技术前提**：确保页面 SSR/SSG 或至少 prerender——纯 CSR 的 Vite SPA 收录效果差，这是 V1 SEO 基建必须解决的问题（可用 vite-ssg / prerender，或迁 Next.js——只在确有必要时迁）。

### 首发与种子社区

| 渠道 | 打法 | 时机 |
|---|---|---|
| r/SomebodyMakeThis | 回到那条原帖："你要的东西我做出来了"——最强的原生叙事 | SEO 基建完成即发 |
| r/Prosopagnosia + 脸盲协会/FB 群组 | 以无障碍工具身份进入，认真收集反馈并公开迭代；他们是最忠诚的布道者 | 同上，长期运营 |
| r/television、单剧 subreddit | 大剧首播周发"S01 无剧透角色指南"链接（遵守版规，先攒 karma） | 每有大剧首播 |
| Product Hunt | "Spoiler-free X-Ray for any show" 角度，攒够 20+ 种子用户好评后发 | 第 4–6 周 |
| Hacker News (Show HN) | 讲技术故事：spoiler shield 的数据处理 + $100 预算 solo build | 与 PH 错开一周 |

## 4. 变现路径与定价

**顺序：广告 → Pro 订阅 → B2B widget。每一步都以前一步的流量/留存达标为前提。**

### ⚠️ 前置：TMDB 商用授权（变现的硬性前提）

- 当前免费 key 仅限个人非商业使用。**挂广告即属商用**，必须先解决授权再放广告，否则 API 被切断 = 产品死亡。
- 行动：上广告前 2–4 周联系 TMDB 商务询价。个人开发者的低流量商用授权历史上有低价先例，但需书面确认。
- 若报价超预算：Plan B 为保持免费无广告攒流量、直接跳到订阅制并同步谈授权；Plan C 评估 Watchmode/Trakt 等替代数据源（质量有损，为最后手段）。

### 阶段一：广告（第 6–10 周）

- 首选 **EthicalAds**（开发者/小众站友好、无 cookie 弹窗负担、不拖慢页面），AdSense 备选。
- 只投放在 SEO 落地页（cast 页、问题页），核心查询流程不放广告——保护口碑与转化。
- 预期：影视类 RPM 约 $1–5，月 5 万 PV 约 $50–250。意义不在金额，在于验证"这个流量能变钱"。

### 阶段二：Pro 订阅（第 10–12 周起，V3 功能就位后）

| | Free | Pro（$4/mo 或 $30/yr） |
|---|---|---|
| 网页查询 + spoiler shield | ✅ | ✅ |
| Watchlist/进度记忆 | ✅ | ✅ |
| 广告 | 有 | 无 |
| 浏览器插件（实时 X-Ray） | — | ✅ |
| AI 无剧透关系图/角色描述 | 每日限量 | ✅ 无限 |
| 观影中实时模式 | — | ✅ |

- 定价 $4/mo 落在 $3–5 区间中位；年付折扣锁现金流。支付用 **Lemon Squeezy 或 Paddle**（merchant of record，替 solo founder 处理全球销售税，Stripe 裸接对个人跨境反而麻烦）。
- 首批 100 名订阅者给脸盲社区终身折扣——回馈种子用户 + 制造首发势能。

### 阶段三：B2B widget（第 12 周后，机会型）

- 媒体每部大片都手工写 character guide → 卖给他们可嵌入的 widget（一段 script，自动生成无剧透角色墙），或按 API 调用收费。
- 不主动重投入，靠 SEO 页面被媒体编辑看到后 inbound 触发；出现 2–3 个 inbound 询价再产品化。

## 5. 成本与预算（$100 怎么花）

### 一次性支出

| 项目 | 金额 | 说明 |
|---|---|---|
| 域名（.com 或 .app） | ~$10/yr | 自有域名是 SEO 与品牌前提，第一优先 |
| Chrome Web Store 开发者注册 | $5 | V3 插件需要，一次性 |
| AI API 试验金（OpenAI/Claude） | ~$10 | V3 角色描述生成，强缓存下够用数月 |
| **预留推广/机动** | ~$75 | 大部分留着：可能的 TMDB 授权费、PH 首发小额投放、或续命 |

### 月度成本（各阶段）

| 阶段 | Vercel | 数据 | AI | 支付 | 合计 |
|---|---|---|---|---|---|
| V1–V2 | $0（免费 tier） | $0 | $0 | — | **$0/mo** |
| V3 无收入期 | $0–20（流量大可能触发 Pro） | TMDB 授权待谈 | <$5（缓存后） | — | **<$25/mo** |
| 变现后 | $20 | 授权费 | <$10 | 抽成 ~5% | 由收入覆盖 |

**原则**：收入为零时月成本必须为零或接近零。任何付费服务（Vercel Pro、AI API 放量）只在对应收入出现后开启。

## 6. 里程碑与指标

### 第 4 周末（V1 收尾 + 首发）

- ✅ SEO 基建完成，首批 500 片页面提交收录；Google 已收录 ≥100 页
- ✅ Reddit 首发完成（SomebodyMakeThis 回帖 + 脸盲社区）
- 🎯 指标：累计访客 ≥1,000；脸盲社区拿到 ≥10 条真实反馈
- **Kill/Continue**：种子社区反馈冷淡（无人回帖、无人回访）→ 重新审视产品形态再投入；反馈热情 → 全速推进 V2

### 第 8 周末（V2 完成）

- ✅ pSEO 问题页上线并收录；集级 shield、OG 分享卡、watchlist、PWA 上线
- ✅ Product Hunt / HN 首发完成
- 🎯 指标：收录 ≥2,000 页；自然搜索流量 ≥300 UV/天且周环比正增长；DAU ≥100；回访率（7 日）≥15%
- **Kill/Continue**：自然流量无增长趋势且收录停滞 → 诊断 SEO 技术问题（渲染/薄页惩罚），修不好则转向纯插件产品路线；流量在涨 → 启动 TMDB 授权谈判 + 上广告

### 第 12 周末（V3 变现验证）

- ✅ 广告上线（授权解决后）；插件 MVP（Netflix）上架；Pro 订阅开闸
- 🎯 指标：自然流量 ≥1,000 UV/天；广告收入 ≥$50/mo；**首笔订阅收入到账**；付费转化 ≥0.5%
- **Kill/Continue**：有流量但无人付费 → 保留网站做广告被动收入，重新评估付费点；订阅有转化 → 全力打磨插件，扩 Disney+/HBO 支持

## 7. 风险与应对

| 风险 | 概率 | 影响 | 应对 |
|---|---|---|---|
| **TMDB 商用授权谈不拢/太贵** | 中 | 致命 | 变现前 2–4 周主动询价，拿书面确认；备选 Watchmode/Trakt；最坏情况维持非商业免费版保住用户，另寻数据源重建 |
| **Google 收录慢/薄页降权** | 高 | 高 | 分批放量（先 500 页做厚），确保 SSR/prerender，Search Console 每周盯收录曲线；同时不把鸡蛋全放 SEO——Reddit/社区流量并行 |
| **Amazon 把 X-Ray 开放到 Prime 外 / 平台自做** | 低 | 高 | 大厂动作慢且只顾自家平台；我们的差异化是**跨平台** + spoiler shield + SEO 占位。真发生则聚焦脸盲无障碍垂直场景与非 Prime 平台 |
| **抄袭者（数据都是公开的 TMDB）** | 高 | 中 | 数据无壁垒，壁垒在：SEO 先发排名、脸盲社区信任关系、spoiler shield 的数据处理细节、插件工程量。跑得快比守得住重要——12 周内做到别人从零追不上 |
| **流媒体改版导致插件失效** | 中（V3 后） | 中 | 插件解析层做成远程配置（selector 可热更新）；只承诺"尽力支持"，网页实时模式作为永久降级方案 |
| **solo founder 精力/范围失控** | 高 | 高 | 本文档即约束：每阶段只做列出的事，kill 标准到点必须执行，不达标不进入下一阶段 |
